01 · INTRODUCTION

🕷️ What Is Nikto?

Nikto is an open-source web server scanner created by Chris Sullo in 2000. It's one of the oldest and most widely used web vulnerability scanners in the security industry. Written in Perl, Nikto performs comprehensive tests against web servers for multiple items, including over 6,700 potentially dangerous files/programs, outdated versions of over 1,250 servers, and version-specific problems on over 270 servers.

Unlike Burp Suite or OWASP ZAP which are full-blown web application testing platforms, Nikto focuses on server-level scanning. It checks for:

  • Dangerous files — backup files, config files, admin panels
  • Default credentials — commonly weak admin passwords
  • Outdated software — known vulnerable server versions
  • Misconfigurations — exposed directories, wrong permissions
  • Server headers — info leakage in HTTP responses
  • Common CVEs — associated with detected server software

For ethical hackers, Nikto is a quick-win tool. It's fast, easy to use, and often finds low-hanging fruit within seconds of starting a scan. It's particularly useful during the early reconnaissance phase of a web pentest.

💡 Note: Nikto is not stealthy. It sends thousands of requests and will appear in server logs immediately. Use it on systems you're authorized to test.

03 · INSTALLATION

⬇️ Installing Nikto

Option 1: Kali Linux (Pre-installed)

Nikto comes pre-installed on Kali Linux. Just run:

nikto -Version

Option 2: Install via APT

sudo apt update sudo apt install nikto

Option 3: Install from Source (GitHub)

git clone https://github.com/sullo/nikto.git cd nikto/program # Run directly from source perl nikto.pl -h target.com # Or install system-wide sudo cp nikto.pl /usr/local/bin/nikto sudo chmod +x /usr/local/bin/nikto

Option 4: Docker

docker run --rm sullo/nikto -h target.com
💡 Note: Always run nikto -update before scanning. This fetches the latest vulnerability database — new checks are added regularly.
04 · BASIC SYNTAX

📝 Basic Nikto Syntax

nikto -h <host> [options]

Essential Flags

FlagPurpose
-h <host>Target host or URL
-p <port>Target port (default: 80)
-sslForce SSL mode (HTTPS)
-o <file>Output file
-F <format>Output format (csv, html, msf, txt, xml)
-Tuning <x>Tune scan behavior
-updateUpdate plugin database
-VersionShow version
-HelpShow all options

Basic Scan Examples

# Scan a single host (HTTP) nikto -h target.com # Scan HTTPS nikto -h https://target.com # Scan on custom port nikto -h target.com -p 8080 # Scan by IP nikto -h 192.168.1.100 # Scan multiple ports nikto -h target.com -p 80,443,8080,8443
05 · YOUR FIRST SCAN

🚀 Running Your First Scan

# Basic scan against Nmap's test server nikto -h scanme.nmap.org # Or scan a local DVWA nikto -h http://localhost:80 # Save output to HTML report nikto -h target.com -o report.html -F html # Save as CSV for spreadsheets nikto -h target.com -o report.csv -F csv

Sample output looks like this:

- Nikto v2.5.0 --------------------------------------------------------------------------- + Target IP: 192.168.1.100 + Target Hostname: target.com + Target Port: 80 + Start Time: 2025-01-15 14:32:00 --------------------------------------------------------------------------- + Server: Apache/2.4.41 (Ubuntu) + /: The anti-clickjacking X-Frame-Options header is not present. + /: The X-Content-Type-Options header is not set. + /robots.txt: Entry '/admin/' is returned by robots.txt. + /admin/: Admin login page found. + /backup/: Directory indexing enabled. + /phpMyAdmin/: phpMyAdmin directory found. + /server-status: Server status page exposed. + OSVDB-3268: /icons/: Directory indexing found. + Apache/2.4.41 appears to be outdated (current is at least 2.4.58). + /index.php: PHP 7.2.34 appears to be outdated.
💡 Reading the Output: Each line starting with + is a finding. Focus on high-impact items like admin panels, backup directories, exposed config files, and outdated software.
06 · CORE OPTIONS

⚙️ Core Nikto Options

Target Specification

# Single host nikto -h target.com # Multiple hosts from file nikto -h targets.txt # Multiple hosts inline nikto -h target1.com,target2.com # With specific port nikto -h target.com -p 8443 -ssl # Using a proxy nikto -h target.com -useproxy http://127.0.0.1:8080

Custom Headers & Cookies

# Custom User-Agent nikto -h target.com -useragent "Mozilla/5.0 (Custom)" # With cookie (authenticated scan) nikto -h target.com -cookies "session=abc123; auth=xyz" # Custom HTTP headers nikto -h target.com -add-header "Authorization: Bearer token123" # With a referer nikto -h target.com -Referer http://google.com

Scan Control

# Set maximum time (seconds) nikto -h target.com -maxtime 300 # Set per-host timeout nikto -h target.com -timeout 10 # Delay between requests (evasion) nikto -h target.com -Pause 2 # Set maximum execution time per host nikto -h target.com -maxtime 1h # Display progress nikto -h target.com -Display V # Don't show 404s nikto -h target.com -no404

Authentication

# HTTP Basic Auth nikto -h target.com -id admin:password # Form-based auth (requires more setup) nikto -h target.com -cookies "PHPSESSID=abc123" # Client certificate nikto -h target.com -cert client.crt -key client.key
07 · TUNING & FILTERS

🎯 Tuning Scan Behavior

The -Tuning option lets you control exactly which types of tests Nikto performs. Useful for reducing scan time and noise.

Tuning ValueScan Type
1Interesting File / Seen in logs
2Misconfiguration / Default File
3Information Disclosure
4Injection (XSS/Script/HTML)
5Remote File Retrieval – Inside Web Root
6Denial of Service
7Remote File Retrieval – Server Wide
8Command Execution / Remote Shell
9SQL Injection
0File Upload
aAuthentication Bypass
bSoftware Identification
cRemote Source Inclusion
xReverse Tuning (exclude listed)

Tuning Examples

# Only check for interesting files (fastest) nikto -h target.com -Tuning 1 # Check for info disclosure + misconfigurations nikto -h target.com -Tuning 23 # Run all tuning types (default behavior) nikto -h target.com -Tuning 1234567890abc # Everything EXCEPT DoS tests (safest) nikto -h target.com -Tuning x6 # Full scan with all checks nikto -h target.com -Tuning 1234567890abcx
⚠️ Warning: Tuning 6 (Denial of Service) can crash systems. Never enable it on production servers without explicit permission.
08 · AUTHENTICATION

🔐 Authenticated Scans

Nikto can scan behind authentication if you provide credentials. This unlocks far more findings — many vulnerabilities only appear after login.

HTTP Basic Auth

nikto -h target.com -id admin:secretpass

Cookie-Based Auth (Form Login)

# Step 1: Log in to the app via browser # Step 2: Copy the session cookie from DevTools # Step 3: Pass it to Nikto nikto -h target.com -cookies "PHPSESSID=abc123def456; auth=xyz789"

Custom Headers (Bearer Tokens)

nikto -h target.com \ -add-header "Authorization: Bearer eyJhbGc..." \ -add-header "X-API-Key: your-api-key"
💡 Pro Tip: Use browser DevTools → Network tab to inspect the login request. Copy the cookie or Authorization header, then pass it to Nikto.

10 · IDS EVASION

🕵️ IDS Evasion Techniques

# Use random User-Agents nikto -h target.com -useragent "Mozilla/5.0 (Windows NT 10.0; Win64; x64)" # Randomize URL encoding (evasion ID 1-8) nikto -h target.com -evasion 1 # Combination of evasion techniques nikto -h target.com -evasion 1234 # Add delays between requests nikto -h target.com -Pause 3 # Use a proxy chain (Burp, Tor, etc.) nikto -h target.com -useproxy http://127.0.0.1:8080 # Custom user agent + evasion + proxy nikto -h target.com -useragent "Mozilla/5.0" -evasion 123 -useproxy http://127.0.0.1:8080

Evasion IDs

IDTechnique
1Random URI encoding (non-UTF8)
2Directory self-reference (/./)
3Premature URL ending
4Prepend long random string
5Fake parameter
6TAB as request spacer
7Change URL case
8Use Windows directory separator (\)
AUse a carriage return / line feed
BUse binary value 0x0B as request spacer
⚠️ Warning: Evasion techniques may cause errors or false positives. Use only when you need to bypass WAF/IDS during authorized testing.
11 · ADVANCED USAGE

🚀 Advanced Techniques

Mutation Techniques

Nikto supports URL mutation techniques used by other scanners:

# Enable mutation techniques nikto -h target.com -mutate 1,2,3 # All mutations nikto -h target.com -mutate 1,2,3,4,5,6 # Mutate only specific directory nikto -h target.com -mutate /admin/

Nikto Databases

# Use specific database files nikto -h target.com -dbcheck # Check database consistency nikto -h target.com -dbcheck # Database locations: # /var/lib/nikto/databases/ # /usr/share/nikto/databases/ # Database files: # - db_404_strings # - db_dictionary # - db_favicon # - db_headers # - db_httpoptions # - db_realms # - db_server_msgs # - db_tests

Scanning Through Burp

# Route Nikto traffic through Burp Suite nikto -h target.com -useproxy http://127.0.0.1:8080 # Now every Nikto request appears in Burp's HTTP history # You can modify, replay, and analyze them

Bulk Scanning

# Scan multiple targets from a file nikto -h targets.txt -o results.txt # Combine with Nmap to discover web servers nmap -p 80,443,8080,8443 --open 192.168.1.0/24 -oG - | \ grep "open" | awk '{print $2}' > web_targets.txt nikto -h web_targets.txt -o bulk_report.html -F html

Automated Pipeline

#!/bin/bash # Full web recon pipeline TARGET="$1" # 1. Nmap discovery nmap -sV -p 80,443,8080,8443 $TARGET -oA nmap_scan # 2. Nikto scan nikto -h $TARGET -o nikto_report.html -F html # 3. Extract URLs from Nikto grep -oE 'https?://[^ ]+' nikto_report.html | sort -u > urls.txt # 4. Feed URLs to other tools cat urls.txt | while read url; do gobuster dir -u $url -w /usr/share/wordlists/dirb/common.txt done
12 · INTEGRATION

🔄 Nikto in the Pentest Workflow

  1. Reconnaissance — Find web servers with Nmap
  2. Nikto scan — Quick first pass for misconfigs and exposed files
  3. Burp Suite — Deeper app-level testing based on Nikto findings
  4. Gobuster/Dirb — Brute-force directories Nikto hinted at
  5. Manual testing — Verify findings and test logic flaws
  6. Metasploit — Exploit verified vulnerabilities
  7. Reporting — Combine Nikto output with other findings

Nikto + Nmap Example

# Step 1: Discover web servers nmap -p 80,443,8080,8443 --open 192.168.1.0/24 -oG web_servers.gnmap # Step 2: Extract IPs with web ports open grep "80/open\|443/open\|8080/open\|8443/open" web_servers.gnmap | \ awk '{print $2}' > live_web.txt # Step 3: Run Nikto on each while read ip; do nikto -h $ip -o nikto_$ip.html -F html done < live_web.txt # Step 4: Combine reports cat nikto_*.html > all_scans.html

Nikto + Metasploit Integration

# Save in Metasploit-compatible format nikto -h target.com -o nikto.msf -F msf+ # Import into Metasploit msf6 > db_import nikto.msf # Now all Nikto findings appear in Metasploit's database # View with: msf6 > vulns msf6 > hosts msf6 > services
13 · BEST PRACTICES

✅ Nikto Best Practices

  1. Update before scanning — Run nikto -update first.
  2. Start with -Tuning 1 — Fastest scan for quick wins.
  3. Use -Display V — Verbose output shows everything.
  4. Save output — Always use -o for reports.
  5. Scan through Burp — -useproxy http://127.0.0.1:8080 for traffic analysis.
  6. Authenticated scans are better — Pass cookies/headers for deeper testing.
  7. Never enable DoS tests — -Tuning 6 can crash systems.
  8. Verify findings manually — Nikto reports many false positives.
  9. Combine with other tools — Nikto alone is not enough.
  10. Respect rate limits — Use -Pause on production systems.

Common False Positives

  • Directory indexing — Sometimes intentional
  • Outdated versions — Check actual patch level
  • Exposed /admin/ — May be intentional admin panel
  • Missing headers — Often low priority
  • robots.txt entries — Sometimes decoys or intentional
14 · LEGAL & ETHICS

⚖️ Legal & Ethical Boundaries

⚠️ Critical Warning: Nikto performs thousands of requests per scan and can trigger alerts, block access, or even crash systems. Using it against servers you don't own or have permission to test is a serious crime.

Before You Scan

  • Get written authorization — Signed scope document.
  • Only scan approved domains — Never stray from scope.
  • Schedule scans off-peak — Avoid disrupting users.
  • Disable DoS tests — Unless explicitly authorized.
  • Use rate limiting — -Pause and -maxtime.
  • Warn the SOC team — So they don't block you or panic.

15 · CONCLUSION

🎓 Final Thoughts

Nikto is a fast, free, and effective web server scanner that belongs in every ethical hacker's toolkit. It's not fancy, it's not stealthy, and it won't find everything — but it will quickly identify the low-hanging fruit that many pentesters overlook.

Use Nikto as your first-pass scanner. Then dive deeper with Burp Suite, Gobuster, and manual testing. Combine Nikto findings with Nmap results and Metasploit exploitation for a complete pentest workflow.

The learning journey:

  1. Learn the basics — nikto -h target.com
  2. Master tuning — Target specific check types with -Tuning
  3. Save reports — HTML, CSV, XML for different use cases
  4. Use authenticated scans — Deeper testing with cookies/headers
  5. Integrate with other tools — Nmap + Nikto + Burp + Metasploit
  6. Practice on legal targets — DVWA, Juice Shop, scanme.nmap.org
